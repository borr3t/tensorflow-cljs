* About this document
This is the verified inventory of the TensorFlow.js (tfjs) surface that tensorflow-cljs
wraps. It is research only; implementation happens in phases 2–5. "Complete wrapper"
(user directive) means tfjs's main surface: the tensor op algebra, layers + models,
optimizers / losses / metrics, =tf.data= pipelines, save / load, callbacks.

*Product constraints that shape everything below:* ClojureScript only (no =^js= hints,
all JS interop confined to ONE binding namespace), kebab-case keyword maps in and out,
promesa promises for asynchronous model operations, tensors as opaque values, zero
runtime npm dependencies beyond =@tensorflow/tfjs=.

** Method and evidence tags
- =[DTS]= — read from the installed package's TypeScript declarations under
  =node_modules/@tensorflow/*/dist/**/*.d.ts= (ground truth for names, arguments, types).
- =[SRC]= — read from the installed package's compiled JavaScript (=dist/**/*.js=) where the
  declarations do not carry the information (registry string tables, banner, priorities).
- =[LIVE]= — observed by running the installed package on node v22.23.2 on 2026-09-25 with
  two throwaway probe scripts (no network, temp files removed). Numbers quoted from these
  runs are single-run wall-clock values on this machine.
- =[NPM]= — from =npm view= on 2026-09-25 (registry metadata; nothing installed beyond
  =@tensorflow/tfjs=).
- =[DOC]= — from the public docs (=https://js.tensorflow.org/api/latest/=, the tfjs GitHub
  repository / issues). Used only for cross-checks and for tfjs-node facts.
Anything not covered by these tags is in section 10 "Pitfalls" or section 11 "Numbered uncertainties".

** Reading conventions
- tfjs names are given verbatim (camelCase); the kebab-case keyword translation is
  mechanical (section 9.4): =kernelInitializer= ↔ =:kernel-initializer=,
  ="glorotUniform"= ↔ =:glorot-uniform=.
- "sync" / "async" in tables is the tfjs call's own nature; the CLJS wrapper keeps sync
  calls synchronous and returns promesa promises for async ones (section 9.3).
- Shapes are vectors of non-negative integers; =null= in a tfjs shape (=[null, 4]=) is the
  unknown batch dimension and appears only in symbolic (layer-graph) shapes.

** 1.4 Variant decision: =@tensorflow/tfjs= (pure JS) vs =@tensorflow/tfjs-node=
House position: *start with pure =@tensorflow/tfjs= (CPU backend)*. Verified locally:
- Installs with zero native steps, no postinstall download, on node v22.23.2 [LIVE].
- 5-line smoke: =tensor2d= ×2, =matMul= → =[[19,22],[43,50]]=, =dtype float32=, =memory()=
  =numTensors 3, numBytes 48= [LIVE].
- Only the =cpu= backend registers; =tf.getBackend()= is =undefined= until the first op or
  =tf.ready()= resolves (lazy backend initialisation) [LIVE].
- Performance baseline (single run, this machine) [LIVE]: 100×100 float32 matmul 32 ms
  (=tf.time= kernelMs); 512×512 matmul + =dataSync= 628 ms (≈0.4 GFLOP/s); =fit= of a
  32→64(relu)→10(softmax) MLP on 1024 samples, batch 32, 3 epochs: 677 ms.
- On the first tensor write the CPU backend prints a banner ("Hi, looks like you are
  running TensorFlow.js in Node.js. To speed things up dramatically, install our node
  backend…") through =console.warn=; it is gated by =env().getBool('IS_TEST') ||
  env().getBool('PROD')= [SRC backend_cpu.js write(), log.js]. =tf.enableProdMode()=
  silences it [LIVE] (uncertainty 11.5).

=@tensorflow/tfjs-node= 4.22.0 (same date, =time.modified= 2025-01-13) [NPM]:
- Depends on =@tensorflow/tfjs= 4.22.0 (same API surface: it re-exports the umbrella and
  swaps the backend to =tensorflow= — native libtensorflow kernels) plus
  =@mapbox/node-pre-gyp= 1.0.9; =engines.node >= 8.11.0=; install script
  =node scripts/install.js= downloads libtensorflow (CPU build 2.9.1 tarball, HTTP 200 on
  the Google Storage bucket [LIVE HEAD]) and the N-API addon.
- Prebuilt addon: =binary.napi_versions [3..8]=, host
  =https://storage.googleapis.com/tf-builds/pre-built-binary=, path
  =./napi-v{n}/{version}/=. =CPU-linux-4.22.0.tar.gz= exists for =napi-v8= (HTTP 200) and
  not for =napi-v7= (404) [LIVE HEAD]. node v22.23.2 reports N-API 10, so node-pre-gyp
  picks the highest listed version (8) → the binary should resolve without a compile.
- Known issue [DOC tensorflow/tfjs#8430 "Support node v22 prebuilt binary" and #8470,
  #8481, #8542, #8566]: some node 22 installs create a =napi-v9= directory while the
  binding lands in =napi-v8=, so the runtime fails to find =tfjs_binding.node=; the reported
  workaround is copying the =napi-v8= directory. Because tensorflow-cljs must have zero
  runtime deps beyond =@tensorflow/tfjs=, tfjs-node stays an *opt-in* backend the consumer
  installs; the binding namespace only needs a =(require "@tensorflow/tfjs-node")= hook
  (uncertainty 11.1). Also: tfjs-node adds =tf.node.*= (a file-system IO handler
  =tf.io.fileSystem=, =tf.node.summaryFileWriter=, =tf.node.decodeImage=/=encodeJpeg=…)
  which the pure package lacks (section 4.7).

Return-shape conventions the wrapper must map [DTS][LIVE]:
- =topk= → ={values, indices}=; =unique= → ={values, indices}=; =moments= → ={mean, variance}=;
  =linalg.qr= → =[q, r]=; =split= / =unstack= → array of tensors; =image.nonMaxSuppressionWithScore=
  / =Padded= and =sparse.*= / =string.stringNGrams= / =stringSplit= → =NamedTensorMap=.
  House rule: object results become kebab maps of opaque tensors ={:values t :indices t}=,
  arrays become vectors.
- dtype promotion [LIVE]: float32 + int32 → float32; int32 ÷ int32 → int32 (7/2 → 3,
  truncating); bool =cast= to float32 → 1.0/0.0; string tensors are rejected by numeric
  ops ("Argument 'a' passed to 'add' must be numeric tensor, but got string tensor").
- Every op accepts =TensorLike= (nested arrays / numbers) in place of a tensor and converts
  internally; the wrapper only passes opaque tensors or CLJS nested vectors (converted in
  the binding namespace) — never CLJS vectors straight to tfjs (they are not arrays).

There is no float64 / int64 / uint8 / float16 tensor dtype in tfjs (=DTYPE_VALUE_SIZE_MAP=
lists only these five). Inference: numbers (even integers) → float32; booleans → bool;

The only places where tfjs data crosses into CLJS values are =data*()=, =array*()=,

=tf.data= is pull-based and promise-per-element (=iterator().next()=). Two CLJS faces:

   (=(data/batch ds 32)=, =(data/map ds f)=, =(data/shuffle ds 100 {:seed "x"})=): =f= is a
   CLJS fn receiving a kebab map (the binding converts the JS element with =js->clj=
   keywordized, tensors left opaque) and returning a map / vector / tensor (converted
   back). This is what =fit-dataset!= / =evaluate-dataset!= consume.
2. *Consumption*: =(data/to-vec! ds)= → promise of a vector; =(data/for-each! ds f)= →
   promise; =(data/chan ds & {:keys [buf]})= → a core.async channel fed by a =go-loop= over
   =next()= (closing on =done=, pushing an =:error= map on rejection) — the house pattern
   already used by leveldb-cljs iterators. A lazy seq is NOT offered (blocking on promises
   is impossible in JS).
Uncertainty 11.10: element conversion cost and tensor ownership across =map=.

Facts that shape the design:
- The layers error classes set the prototype but *not* =name=, so =e.name= is always
  "Error"; the class is only visible as =e.constructor.name= (=e instanceof= is not
  possible either: =ValueError= etc. are not exported from the umbrella — =tf.ValueError=

** 9.2 Tensors as opaque values (house rule)
The tfjs =Tensor= object itself is the opaque value (wrapping it in a record would force
an unwrap on every op call and break =tidy='s container walk). Consumers may only
=(tf/tensor? x)=, pass it to wrapper fns, or read it out through =->vec= / =data-sync=.
=print= / =toString= are exposed as =(tf/->string t)=. Equality is identity; =(tf/->vec t)=
is the way to compare. Symbolic tensors, layers, models, optimizers, datasets and io
handlers are opaque the same way (=symbolic?=, =layer?=, =model?=… predicates via
=instance?= checks live in the binding namespace).

** 9.3 Promises vs sync
| Sync (returns a value)                         | Async (returns a promesa promise, suffix =!=) |
|------------------------------------------------+--------------------------------------------|
| every op, creation, =tidy=, =dispose!=, =memory=, =backend=, =predict=, =evaluate=, =compile!= (sync in tfjs but suffixed =!= for side effect), =summary=, =get-weights=, layer construction, dataset combinators | =fit!= =fit-dataset!= =train-on-batch!= =evaluate-dataset!= =save!= =load-model!= =model-from-json!= =data!= =->vec!= =bytes!= =set-backend!= =ready!= =profile!= =time!= =to-vec!= =for-each!= =next!= =where!= =boolean-mask!= =in-top-k!= =setdiff1d!= =optimizer-weights!= =column-names!= |
Convention: =!= marks side effects AND asynchrony where they coincide; purely sync side
effects (=assign!=, =set-weights!=, =dispose!=, =add!=) also carry =!= (house style).

** 9.4 Config translation (kebab keys → camelCase)
=util/->config= (phase 0, tested): keys =kebab->camel=; keyword *values* → registry strings
via =enum-value= (=:glorot-uniform= → ="glorotUniform"=, =:categorical-crossentropy= →
="categoricalCrossentropy"=, =:channels-last= → ="channelsLast"=, =:same=, =:relu=, =:gelu-new= →
="geluNew"= ✗ — tfjs spells it ="gelu_new"=; and =:hard-sigmoid= → ="hardSigmoid"= ✓). The
=gelu_new= exception is the ONE non-camel activation identifier (uncertainty 11.13). Shapes
stay numeric vectors (→ JS arrays); nested maps recurse; =nil= dropped; pass-through
subtrees (=:metadata=, =:weights=, =:callbacks=, =:inputs=, =:outputs=, =:tensors=) untouched.
Results (=History.history=, logs, =memory()=, summaries, =ModelArtifactsInfo=) come back
through =->kebab-keys= (=val_loss= → =:val-loss=, =numTensors= → =:num-tensors=). Layer names
(="dense_Dense1"=) and weight names (="dense_Dense1/kernel"=) are VALUES and stay verbatim.

** 9.5 :dtype mapping
=util/dtype->str= accepts =:float32 :int32 :bool :string :complex64= (and their strings),
rejects anything else with =:argument-error= (there is no =:float64=; JS numbers are
silently narrowed — document loudly). Readers map =bool= storage (Uint8 0/1) to CLJS
=true=/=false= in =->vec= (extra pass on bool tensors only); =complex64= readers return the
interleaved flat vector and =(ops/real t)= / =(ops/imag t)= are the recommended path.

* 10. Pitfalls (settled)
- *float32 only*: every CLJS double is rounded to float32 on entry; integers above 2²⁴
  lose precision as float32, =int32= wraps at 2³¹; CLJS has no ratio type and JS BigInt is
  rejected by =tensor()= (not a number). House: documentation + =:argument-error= for BigInt.
- *bool arraySync returns 1/0* — convert explicitly.
- *complex64 is interleaved* in both =dataSync= and =arraySync= (shape reports the logical
  size).
- *No file:// handler in pure tfjs* — =save('file://…')= rejects, =loadLayersModel('file://…')=
  rejects with the misleading "fetch failed". Phase 4 ships a CLJS fs handler using the
  =model.json= + =weights.bin= layout.
- *fit() is exclusive* per model (second concurrent call rejects) and an uncaught failing
  =fit= is an unhandled rejection.
- *Memory*: nothing outside =tidy= is freed; =evaluate= returns Scalars that must be
  disposed; model weights are Variables (freed by =model.dispose()= /
  =disposeVariables()=); =memory().numTensors= is the leak detector (test fixture in
  phase 2).
- *tidy* only takes synchronous fns; async work must =keep= or run outside.
- *Shape inference errors* are strings only (=ValueError= "expected … to have shape
  [null,3] but got array with shape [1,2]"); wrapper maps to =:shape-error= /
  =:value-error= by heuristics — messages are the contract.
- *CPU perf*: ≈0.4 GFLOP/s matmul; small MLPs train in well under a second per few
  thousand samples; CNNs on images will be slow (minutes). tfjs-node is the fix, not
  wrapper work.
- *Loss / metric identifiers are camelCase only* at =compile= (snake_case and =mse=
  aliases are rejected there; =mse= IS valid as a metric name).
- *Optimizer defaults differ by construction path*: ="adam"= string → lr 0.001; supplying
  a learning rate requires the =train/adam= object.
- *getLayer by index* needs =(undefined, index)=.
- *Banner* on first tensor write under node unless PROD / IS_TEST.
- *version churn*: 4.x has been stable since 2023 (4.22.0 Jan 2025, 4.23 only at rc); the
  3.x → 4.x changes (removal of =tf.io.browserHTTPRequest= deprecation paths, dropped
  =Tensor.flatten=/=as1D=-style chained helpers, =tf.data= typed containers, TypeScript 4.9
  types) are already reflected in the installed declarations — this inventory is 4.22.0
  only.
